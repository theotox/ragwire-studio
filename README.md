# Local AI Factory: Αυτόνομη Ανάπτυξη Εφαρμογής με OpenCode & Τοπικό Hardware

Αυτό το repository δεν είναι απλώς άλλη μία εφαρμογή RAG. Είναι η απόδειξη του τι μπορεί να πετύχει ένα **100% τοπικό "AI Software Factory"** — χωρίς cloud, χωρίς συνδρομές API και χωρίς να φεύγει ούτε ένα byte δεδομένων εκτός του δικού μας συστήματος.

---

## 🎯 Τι Εξετάζουμε Εδώ;

Στόχος αυτού του εγχειρήματος ήταν να επιβεβαιώσουμε στην πράξη αν ένα μικρό σύστημα, ένα glorified  Game PC — που ναι μεν δεν είναι φθηνό, αλλά δεν είναι και εξωπραγματικά ακριβό— μπορεί να λειτουργήσει ως αυτόνομη μηχανή παραγωγής λογισμικού υψηλών απαιτήσεων:

* **Motherboard:** Γενικής χρήσης (consumer/desktop) Gigabyte AM5
* **Επεξεργαστής:** AMD Ryzen 9 9900X 
* **Μνήμη RAM:** 96GB *(θα μπορούσε να λειτουργήσει και με 64GB)*
* **Κάρτα Γραφικών:** Μία «παιχνιδόκαρτα» GeForce RTX 5090 με **32GB VRAM** *(με υποδοχές για οθόνες — όχι κάποιος πανάκριβος datacenter επιταχυντής AI, ενώ θεωρητικά θα μπορούσε να στηθεί και με κάρτα που θα είχε 24GB VRAM)*
* **Αποθηκευτικό μέσο:** 1x M.2 NVMe SSD 2TB, θα αρκούσε και ένα 512GB

Πάνω σε αυτό το hardware, σε ένα Ubuntu Server 24.04.5LTS και Cuda 13.1, στήθηκε τοπικά η μηχανή inference με το μοντέλο **`edge0-145B-nvfp4`** ([δείτε το σχετικό βίντεο εδώ](https://youtu.be/eax4EDKuiOg)), 

Σε ένα εικονικό μηχάνημα ubuntu server που έτρεχε σε ένα LXC σε ένα miniPC των 300 ευρώ απο AliExpress, εγκαταστάθηκε το open-source coding agent **OpenCode**.
Σε αυτο το μηχάνημα μπήκε το opencode.json που υπάρχει στο repository το οποίο επέτρεπε στο opencode agent να χρησιμοπoιήσει το edge0-145B.

Η δοκιμή που έκανα ήταν ένας πραγματικός έλεγχος αντοχής και ικανοτήτων:
1. Του ίδιου του **μοντέλου** (`edge0-145B-nvfp4`),
2. Της **μηχανής inference**, και
3. Του **OpenCode** ως αυτόνομου agent ανάπτυξης.

## 🧠 Το Κλειδί της Επιτυχίας: Να Ξέρεις Τι Ζητάς

Ήθελα να βάλω στο σύστημα έναν δύσκολο, ρεαλιστικό στόχο. Επειδή είχα σε εκκρεμότητα να δοκιμάσω στην πράξη το framework **[RAGWire](https://laxmimerit.github.io/RAGWire/)**, αποφάσισα να ζητήσω από το **OpenCode** να χτίσει αυτόνομα μία πλήρη, multi-user εφαρμογή (**RAGWire Studio**) αντίστοιχη με εφαρμογές που είχα φτιάξει στο παρελθόν «με το χέρι».

Το σημαντικότερο δίδαγμα της διαδικασίας είναι ότι το αποτέλεσμα δεν ήρθε τυχαία:
* **Ήξερα τι θέλω** (από προηγούμενη εμπειρία με "hand-made" RAG pipelines),
* **Ήξερα τι να ζητήσω** (όρια context στον reranker, προστασία KV slots, ασφάλεια αρχείων, RBAC, cascade deletion), και
* **Ήξερα πώς ήθελα να γίνει**.
* Επίσης **ήξερα τα προαπαιτούμενα** για να λειτουργήσει μία εφαρμογή RAG, δηλαδή την ανάγκη για 3 μοντέλα (embedding, reranker, chat), structured & vector DB κλπ
Από τα 3 μοντέλα, το βαρύ είναι το chat, τα υπόλοιπα θα μπορούσαν να τρέξουν και σε CPU οπότε ένα οποιοδήποτε σύστημα με 8GB RAM θα μπορούσε να τα φιλοξενήσει, ακόμα και ένα παλιό laptop.
Σαν **chat** μοντέλο, θα χρησιμοποιούσα το ίδιο μοντέλο με το οποίο θα γραφόταν το πρόγραμμα, το edge0-145B

Με αυτή τη γνώση και το κριτήριο, συνεργάστηκα αρχικά με ένα chatbot ώστε να συντάξουμε ένα αυστηρό, πλήρως δομημένο αρχιτεκτονικό specification (`to-do.txt`) — το πραγματικό prompt που δόθηκε στο OpenCode για να εκτελέσει τη δουλειά αυτόνομα.
To αρχείο αυτό (to-do.txt) βρίσκεται στο repository.
Αξίζει να σημειωθεί η πολύτιμη συνεισφορά του chatbot στο να φτιαχτεί το prompt, καθώς εμείς (οι άνθρωποι) έχουμε την τάση να θεωρούμε κάποια πράγματα δεδομένα ή αυτονόητα και αυτο δεν ισχύει απαραίτητα!
Οπότε, πρέπει να είμαστε σαφείς και συγκεκριμένοι στο τι ζητάμε.

## ⏱️ Το Αποτέλεσμα: 148 Λεπτά & Έκδοση `v1.0.1`

Το OpenCode ανέλαβε το `to-do.txt` και δούλεψε **εντελώς αυτόνομα για 148 λεπτά**, χτίζοντας το backend, το frontend, το Docker Compose setup, τα management scripts και τον installer, φτάνοντας στην έκδοση **`v1.0.0`**, η οποία λειτουργούσε σύμφωνα με τις προδιαγραφές.

H εντολή που έδωσα στο OpenCode ήταν:
  **Read @to-do.txt and execute all phases autonomously until version 1.0.0 is reached and verified.**

Τονίζω πως αυτό που έχει σημασία δεν είναι τόσο η εφαρμογή που πρόέκυψε όσο η εντολή που δόθηκε.
Το to-do.txt στην πραγματικότητα είναι το **blueprint**, το κατασκευαστικό σχέδιο της εφαρμογής και θεωρητικά, αν δοθεί σε κάποιο άλλο ικανό Coding Agent (πχ Claude Code?) τότε το όποιο coding agent θα πρέπει να δημιουργήσει μία αντίστοιχη εφαρμογή.

Και να κάνω μία πρόβλεψη για το μέλλον: με δεδομένο ότι το software όπως το ξέρουμε δεν θα υπάρχει για πολύ ακόμα με αυτή την μορφή, ενδέχεται στο μέλλον να πωλούνται blueprints για την κατασκευή λογισμικού και όχι software έτοιμο προς χρήση.

**(Θυμηθείτε, ότι αυτό για την αγορά Software Blueprints που ΘΑ υπάρξει, το διαβάσατε πρώτα εδώ!)**

Επιστροφή στην περιγραρή της δοκιμής που έκανα:

Κατά τον έλεγχο εντοπίστηκε **μία μόνο** παράλειψη: έλειπε το κάθετο scrollbar στο παράθυρο των απαντήσεων, οπότε ο άνθρωπος-χρήστης δεν μπορούσε να δει παρά τις λίγες πρώτες γραμμές μίας απάντησης. Επειδή στο αρχικό specification είχε δοθεί εντολή στο OpenCode να χρησιμοποιεί το **Playwright** (εργαλείο αυτοματοποιημένου end-to-end testing σε πραγματικό browser), το OpenCode εντόπισε το πρόβλημα, το διόρθωσε, επιβεβαίωσε ξανά τη σωστή λειτουργία και παρήγαγε την έκδοση **`v1.0.1`**.

> **Συμπέρασμα:** Το ζητούμενο εδώ δεν είναι απλώς το ίδιο το πρόγραμμα που παρήχθη. Το πραγματικό συμπέρασμα είναι **η δύναμη του σωστά δομημένου prompt**, η διαδικασία με την οποία σχεδιάστηκε, και η απόδειξη ότι τα σύγχρονα τοπικά μοντέλα είναι πλέον έτοιμα για **υψηλής ποιότητας αποτέλεσμα σε δύσκολους, πολύπλοκους στόχους** — 100% τοπικά, είτε το κίνητρο είναι το μηδενικό κόστος χρήσης είτε η απόλυτη ασφάλεια και ιδιωτικότητα των δεδομένων.

## 📂 Περιεχόμενα του Repository

* **`to-do.txt`** — Το πλήρες prompt / αρχιτεκτονικό specification που σχεδιάστηκε και δόθηκε στο OpenCode.
* **`opencode.json`** — Το αρχείο ρυθμίσεων του OpenCode για τη σύνδεση με το τοπικό μοντέλο.
* **`ragwire-studio-installer-v1.0.1.sh`** — Το αυτοτελές, version-marked εγκαταστάσιμο script της εφαρμογής στην έκδοση `v1.0.1`.
* **`ragwire_studio_userguide.md`** - οδηγίες χρήσης της εφαρμογής.
