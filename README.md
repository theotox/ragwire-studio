# Local AI Factory: Αυτόνομη Ανάπτυξη Εφαρμογής με OpenCode & Τοπικό Hardware

Αυτό το repository δεν είναι απλώς άλλη μία εφαρμογή RAG. Είναι η απόδειξη του τι μπορεί να πετύχει ένα **100% τοπικό "AI Software Factory"** — χωρίς cloud, χωρίς συνδρομές API και χωρίς να φεύγει ούτε ένα byte δεδομένων εκτός του δικού μας συστήματος.

---

## 🎯 Τι Εξετάζουμε Εδώ;

Στόχος αυτού του εγχειρήματος ήταν να επιβεβαιώσουμε στην πράξη αν ένα σύστημα που —ναι μεν δεν είναι φθηνό, αλλά δεν είναι και εξωπραγματικό— μπορεί να λειτουργήσει ως αυτόνομη μηχανή παραγωγής λογισμικού υψηλών απαιτήσεων:

* **Motherboard:** Γενικής χρήσης (consumer/desktop)
* **Επεξεργαστής:** AMD Ryzen 7 (R7)
* **Μνήμη RAM:** 96GB *(αν και θα μπορούσε να λειτουργήσει και με 64GB)*
* **Κάρτα Γραφικών:** Μία «παιχνιδόκαρτα» GeForce RTX 5090 με **32GB VRAM** *(με υποδοχές για οθόνες — όχι κάποιος πανάκριβος datacenter επιταχυντής, ενώ θεωρητικά θα μπορούσε να στηθεί και με 24GB VRAM)*
* **Αποθήκευση:** 1x M.2 NVMe SSD

Πάνω σε αυτό το hardware στήθηκε τοπικά η μηχανή inference με το μοντέλο **`edge0-145B-nvfp4`** ([δείτε το βίντεο της εγκατάστασης εδώ](https://youtu.be/eax4EDKuiOg)), σε συνδυασμό με τον open-source coding agent **OpenCode**.

Ήταν ένας πραγματικός έλεγχος αντοχής και ικανοτήτων:
1. Του ίδιου του **μοντέλου** (`edge0-145B-nvfp4`),
2. Της **μηχανής inference**, και
3. Του **OpenCode** ως αυτόνομου agent ανάπτυξης.

---

## 🧠 Το Κλειδί της Επιτυχίας: Να Ξέρεις Τι Ζητάς

Θέλαμε να βάλουμε στο σύστημα έναν δύσκολο, ρεαλιστικό στόχο. Επειδή ήθελα να δοκιμάσω στην πράξη το framework **[RAGWire](https://laxmimerit.github.io/RAGWire/)**, αποφάσισα να του ζητήσω να χτίσει αυτόνομα μία πλήρη, multi-user εφαρμογή (**RAGWire Studio**) αντίστοιχη με εφαρμογές που είχα φτιάξει στο παρελθόν «με το χέρι».

Το σημαντικότερο δίδαγμα της διαδικασίας είναι ότι το αποτέλεσμα δεν ήρθε τυχαία:
* **Ήξερα τι θέλω** (από προηγούμενη εμπειρία σε χειροκίνητα RAG pipelines),
* **Ήξερα τι να ζητήσω** (όρια context στον reranker, προστασία KV slots, ασφάλεια αρχείων, RBAC, cascade deletion), και
* **Ήξερα πώς ήθελα να γίνει**.

Με αυτή τη γνώση και το κριτήριο, συνεργάστηκα αρχικά με ένα chatbot (Gemini) ώστε να συντάξουμε ένα αυστηρό, πλήρως δομημένο αρχιτεκτονικό specification (`to-do.txt`) — το πραγματικό prompt που δόθηκε στο OpenCode για να εκτελέσει τη δουλειά αυτόνομα.

## ⏱️ Το Αποτέλεσμα: 148 Λεπτά & Έκδοση `v1.0.1`

Το OpenCode ανέλαβε το `to-do.txt` και δούλεψε **εντελώς αυτόνομα για 148 λεπτά**, χτίζοντας το backend, το frontend, το Docker Compose setup, τα management scripts και τον installer, φτάνοντας στην έκδοση **`v1.0.0`**, η οποία λειτουργούσε σύμφωνα με τις προδιαγραφές.

Κατά τον έλεγχο εντοπίστηκε **μία μόνο** παράλειψη: έλειπε το κάθετο scrollbar στο παράθυρο των απαντήσεων. Επειδή στο αρχικό specification είχε δοθεί εντολή στο OpenCode να χρησιμοποιεί το **Playwright** (εργαλείο αυτοματοποιημένου end-to-end testing σε πραγματικό browser), το OpenCode εντόπισε το πρόβλημα, το διόρθωσε, επιβεβαίωσε ξανά τη σωστή λειτουργία και παρήγαγε την έκδοση **`v1.0.1`**.

> **Συμπέρασμα:** Το ζητούμενο εδώ δεν είναι απλώς το ίδιο το πρόγραμμα που παρήχθη. Το πραγματικό συμπέρασμα είναι **η δύναμη του σωστά δομημένου prompt**, η διαδικασία με την οποία σχεδιάστηκε, και η απόδειξη ότι τα σύγχρονα τοπικά μοντέλα είναι πλέον έτοιμα για **υψηλής ποιότητας αποτέλεσμα σε δύσκολους, πολύπλοκους στόχους** — 100% τοπικά, είτε το κίνητρο είναι το μηδενικό κόστος χρήσης είτε η απόλυτη ασφάλεια και ιδιωτικότητα των δεδομένων.

## 📂 Περιεχόμενα του Repository

* **`to-do.txt`** — Το πλήρες prompt / αρχιτεκτονικό specification που σχεδιάστηκε και δόθηκε στο OpenCode.
* **`opencode.json`** — Το αρχείο ρυθμίσεων του OpenCode για τη σύνδεση με το τοπικό μοντέλο.
* **`ragwire-studio-installer-v1.0.1.sh`** — Το αυτοτελές, version-marked εγκαταστάσιμο script της εφαρμογής στην έκδοση `v1.0.1` (οδηγίες χρήσης της εφαρμογής θα προστεθούν σε επόμενη φάση).
